# 因子研究工作台（本地合成数据示例）

工作台从 `holdout-governance 0.5.0` 开始提供；`0.4.3` 不包含这项能力。
这是可信本地工作流的合成示例，下面的隔离限制与一次性评估规则仍适用。

这套示例把真实的因子计算、训练、筛选、模型参数搜索与 Holdout 门禁串联起来。
它来自维护者希望展示内部研究系统脱敏能力的需求；本示例新写的搜索器并不是
内部策略代码，也不是 AutoScientist-Quant 的完整复现。

## 打开与使用

Windows 上双击仓库中的 `Start-Factor-Research.cmd`。它优先使用仓库 `.venv`
中的 Python，再查找已安装的 Python；缺少 Python 或依赖时会保留窗口并给出
安装说明，不会创建研究或使用最终测试数据。Python 需为 3.11 或更新版本，带 Tcl/Tk。
也可用完整路径运行 `python examples/factor_research.py`；脚本从自己的位置找到仓库，
不要求终端当前位于项目目录。

首次在另一台电脑安装：

```sh
python -m venv .venv
.venv\Scripts\python.exe -m pip install -e ".[research]"
```

以上 Windows 命令在仓库目录运行；macOS/Linux 对应解释器为 `.venv/bin/python`。
安装 0.5.0 的源码或 wheel 后，可在任意目录运行 `holdout-research`。
使用发布包时运行 `python -m pip install "holdout-governance[suite,research]==0.5.0"`。
用 `holdout-research --check` 或 `python examples/factor_research.py --check` 仅检查环境。
`holdout-research --dir "保存目录"` 可明确选择研究保存位置。

1. 选择放量滞涨、短期动量或短期反转，填写研究问题和12–100次试验预算。
2. 点击“开始新研究”，查看三个阶段的候选、实际反馈指标和淘汰理由。
3. 搜索完成且存在可评估候选时，点击“冻结候选”。
4. 点击“最终评估（一次）”。点击后会先消耗评估机会，再读取测试数据。
5. 点击“打开报告”查看完整方案、模型系数、窗口、统计检查和证据清单。

每轮研究保存在 `research-runs/run-日期-随机编号/`。刷新或重启后，使用
“打开已有研究”选择其中的 `research.sqlite`，次数和状态会保留。
如果研究已登记但搜索尚未开始，可点击“继续搜索”；已中断的搜索不能重跑来清零次数。
仓库双击入口使用仓库中的 `research-runs`；安装后的 `holdout-research` 默认使用
用户目录 `.holdout/research-runs`，不会随终端所在目录变化。
打开迁移后的研究时，报告的动态检查入口会重新绑定当前目录，避免检查原位置的另一份文件。
继续操作要求研究程序和依赖仍与登记时一致；升级后的程序会拒绝继续旧版本研究，
不会清零机会。保留原环境可继续核验；旧的 `report.html` 和 `summary.json` 可直接查看。
无合格候选时不会伪造一个赢家，冻结和最终评估按钮保持不可用。

## 它实际计算什么

- 固定种子生成24个合成资产；内置可学习信号，明确不是市场校准数据。
- 六个基础特征：5期/20期动量、成交量扰动、两种放量滞涨交互、5期反转。
- 学习目标是下一期收益；使用线性模型及不同正则强度，不调用大模型。
- 研究方向决定初始候选顺序；问题文字用于预注册，不是自然语言自动编程入口。
- 训练窗口拟合系数；验证窗口要求扣费后均值为正；反馈窗口按年化 Sharpe
  排序。各参数配置分别计次，不把隐藏参数网格算作“一次”。
- 每个窗口按分数选前5个资产等权持有，成本为单边换手金额的10个基点，
  包含首次建仓和最后清仓。压力检查将成本翻倍。
- 报告中的“日均收益年化”是日均净收益乘252，不是复合年化收益，也不是相对
  指数的超额收益。窗口末尾一条跨界收益标签被剔除。
- 搜索器会根据停滞情况选择 Improve/Combine/Pivot，并在候选空间完成或
  改进不足时 Stop。阶段探索上限为简单启发式，剩余预算不强行消耗；这不是
  论文的大模型控制器，也没有宣称支持任意跨阶段预算重新分配。

## 真正调用的工具

| 工具 | 本示例中的作用 |
| --- | --- |
| lookahead-free | 对受控特征生成器的可用时间声明运行时序检查；故意注入一个 future_return 候选作为故障对照 |
| factor-qc | 对反馈期全部有收益序列的试验计算质量检查与 PBO；最终期仅检查冻结赢家，保留全部尝试次数 |
| falsification-ledger | 研究前登记方案与必需判据；最终逐项核对并追加裁决，检查哈希链 |
| lesson-book | 在同一输出父目录存储、检索合成研究的时序失败教训 |
| holdout-governance | 输出实际 artifact/policy；可用 gov check 重新执行动态审计门禁 |

没有真实行情或公司行为数据，因此本示例不假装已运行 ashare-data-immunity
与 pit-adjuster。接入实际系统时，这两层应在数据进入研究前补上。

## 命令行及现有系统接入

```sh
python -m holdout_governance research create --dir research-runs/example --budget 30
python -m holdout_governance research search --dir research-runs/example
python -m holdout_governance research freeze --dir research-runs/example
python -m holdout_governance research evaluate --dir research-runs/example --reviewer operator
python -m holdout_governance research audit --dir research-runs/example
python -m holdout_governance check --manifest research-runs/example/evidence/artifact.json
```

`research audit` 是只读检查，不会重新打开测试数据。`gov check` 的研究门禁
会从 SQLite 事件、冻结指纹和评估结果重新取证，不只是相信先前导出的状态。
最终评估由人触发不等于人已经批准研究结论；示例不会自动写入人工批准。

新增研究命令成功退出0、操作被拦或用法/环境错误退出2；只读 `research audit`
检查不通过退出1。通过流程检查仍不保证统计质量通过。

## 隔离与证据的准确边界

- 搜索函数只加载 training、validation、feedback 三份文件；最终评估入口才加载
  custody/test.npz。候选是受控特征列表和参数，不执行外部代码。
- 数据库事务在计算前保留试验；失败或中断不清零预算。最终读取机会也在访问前
  原子消费，并发请求、重启、失败后重试都不能再次开启本轮测试。
- 方案、数据、研究模块、运行环境、候选与结果有指纹；记录在冻结后不能通过
  正常入口修改。哈希链可发现内容变化，但它不是外部可信时间戳。
- **本地工作流隔离不等于操作系统级沙箱。** 同一账号可以读写研究文件，亦可
  重写整个账本或复制数据。对不受信任的代理，应将托管数据和评估进程放到
  代理无法访问的独立账号/机器；本示例尚未提供该部署隔离。
- 固定种子的合成数据公开可重建，新建目录不是新的未见数据；不能把多次演示
  当成多份独立证据。本地共用登记处现在会拦截已登记的跨研究重复使用，
  但无法证明公开可重建的合成数据从未被人见过。
- 依赖版本被冻结，但版本号不能证明依赖源码未被同版本修改；本例不是供应链审计。

## 验证

```sh
python -m pytest tests/test_research.py tests/test_research_ui.py tests/test_research_launcher.py -q
```

测试包括：测试区数据改变不影响搜索候选、搜索不加载测试区、标签边界、
真实门禁、失败试验计数、冻结内容篡改、并发最终评估、重启重复评估和测试读取失败。
启动预检不创建研究；现有数据库临开时消失不会被重建，测试登记不会初始化其他业务库。
桌面按钮测试在没有可用显示窗口时跳过，不将跳过计为界面已验证。

## 跨研究的最终测试使用登记

新研究共用当前用户目录下的 `.holdout/test-use.sqlite`，不会随研究输出目录
改变。研究方案冻结登记处身份、样本身份和登记程序指纹；复制一个研究目录
不会获得新的测试机会。可通过 `HOLDOUT_TEST_REGISTRY` 指定团队保管方的登记路径，
但这属于可信部署配置：**换一个空库不会让曾经见过的数据恢复独立性**。
测试套件使用隔离的临时登记处，避免污染实际使用记录。

登记按保管方提供的来源标识、资产标识和标签时间区间识别样本，不按文件名
或文件字节识别。相同样本换顺序、重新导出、改变研究问题仍属于同一份测试。
同一来源、同一资产的标签时间有任何重叠（包括端点）都会被拒绝；这是保守的
固定政策，不提供例外次数或清零按钮。互不重叠的新样本可以申请。真实数据接入
必须统一来源/资产别名；系统无法自行识破保管方故意提供的假来源。

评估前在共用库内原子占用机会，绑定研究身份、冻结候选和结果接收人，然后才
打开测试文件。失败、中断、研究目录恢复到旧备份均不退还机会。同一个请求
再次调用登记接口只返回已有凭证，不重新授予执行权；工作台重复评估会报告
拒绝。完成凭证绑定结果指纹，`research audit` 和 `gov check` 会实时核验它。
登记处丢失、身份改变或完成凭证缺失时，门禁失败，不信任本地旧的通过报告。

独立身份文件用于发现意外删除/替换数据库。两份文件必须一起备份和恢复；
回滚整个登记库、换库或拥有文件权限的人直接改库仍超出当前防护能力。
这是一套可信本地工作流协议，尚不是独立账户托管的评估服务，也不是防篡改
外部审计日志。没有提供针对恶意代理的操作系统权限隔离。

### 已经看过的旧数据

升级不会自动证明旧测试集干净。对于本工作台的旧合成研究，由保管方补登记：

```sh
python -m holdout_governance research record-exposure --dir research-runs/old-study --reviewer custodian
```

此入口核验历史方案和数据指纹，仅读取样本日期，登记“已暴露”通知；不重新
评分、不认可旧结论，也不要求旧研究程序仍能运行。即使旧研究没有正式评估，
保管方知道数据曾被其他途径看过，也可保守登记。其他历史数据必须在接入前由
保管方完成暴露清点；未登记的历史不能从本工具推断为未暴露。

固定种子演示第一次登记评估后，新建研究仍可搜索和冻结，但最终评估会被
拦截。界面禁用该按钮并说明原因。合成示例没有“换种子重新考试”入口。

```sh
python -m pytest tests/test_test_registry.py tests/test_research.py tests/test_research_ui.py -q
```

新增验证覆盖重排、重叠、并发、重复请求、失败不返还、跨目录复制、
共用登记后本地事务失败、登记库丢失、结果凭证核验与历史暴露补登记。
